# l0-debug-mindset — Debugging Mentality & Stack Traces

Concept: Converting "it broke" into a located, minimal, explained failure: read a Python traceback bottom-up; separate symptom from cause; bisect code/data/config; form ONE hypothesis at a time and test it; choose the right probe (print vs logging vs debugger). This is a method node — the tools are props, the hypothesis discipline is the skill.

Learner prerequisites: l0-terminal (run scripts, read output). Concurrent early Python (L1 starts in parallel) is enough — the drills use 5–20-line scripts whose *language* content is trivial by design so the *method* is the load. Feeds every later level; the node's misconception field is the thesis: the error message is not the enemy, it is the single most informative artifact you have.

What beginners commonly misunderstand:
- They don't read the error — they see red, feel judged, and re-run or paste it to an AI whole; the official Python tutorial's key sentence ("The last line of the error message indicates what happened") is genuinely unknown to most beginners.
- Which frame is theirs: a 15-line traceback through 3 library layers reads as library's fault; the skill is scanning bottom-up for the last frame in *your* code.
- Shotgun debugging: changing several things at once, so even a fix teaches nothing — the one-hypothesis-at-a-time log is the antidote and is exactly what this node grades.
- Symptom vs cause: fixing where it *crashed* rather than where it *went wrong* (the crash site is often innocent downstream code — e.g. the bad path was built 30 lines earlier).
- That AI assistance replaces the skill: with this learner's heavy Claude/ChatGPT use, the failure mode is outsourced diagnosis — the packet uses AI only AFTER a written hypothesis, as the 2026 Missing Semester lecture itself now frames it ("LLMs as debugging assistants, with limitations").

The silent-logic-bug script exists specifically because no traceback appears — proving the method survives the absence of its favorite artifact.
